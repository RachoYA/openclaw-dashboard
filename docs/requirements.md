> **Версия:** 1.0  
> **Дата:** 2026-03-20  
> **Автор:** Лена (аналитик)  
> **Заказчик:** Грачья  
> **Концепция:** Анимированная визуализация работы AI-агентов в реальном времени

---

## 1. Концепция продукта

### 1.1 Elevator Pitch

> Представьте The Sims, но вместо людей — ваши AI-агенты. Вы открываете дашборд и видите виртуальный офис: Артём (PM) стоит у доски и распределяет задачи, Коля (Dev) сидит за компьютером и пишет код, Лена (аналитик) изучает документы, Саша (QA) тестирует систему. Над каждым — пузырь с текущим действием. Между ними летают сообщения. Вы в реальном времени видите кто чем занят — без единого вопроса в чат.

### 1.2 Проблема

- Руководитель постоянно спрашивает «кто что делает?» в чат
- Статусы агентов разбросаны: Telegram, GitHub, логи
- Нет единой картины происходящего в команде
- Текстовые отчёты скучные и не дают «ощущения» работы

### 1.3 Решение

Анимированный веб-дашборд, где каждый агент — персонаж в виртуальном офисе. Действия агентов визуализируются как анимации. Данные — в реальном времени из OpenClaw API.

### 2.2 Персонажи (агенты)

Каждый агент отображается как анимированный персонаж:

| Элемент | Описание |
|---------|----------|
| **Аватар** | Пиксельный / low-poly персонаж (стиль Sims/pixel art) |
| **Имя + роль** | Подпись под аватаром: «Артём, PM» |
| **Статус-бабл** | Облачко над головой с текущим действием |
| **Индикатор** | 🟢 активен / 🟡 idle / 🔴 ошибка / 💤 спит |
| **Анимация** | Зависит от текущего действия (см. п.2.3) |
| **Прогресс** | Мини-прогрессбар под персонажем (% выполнения задачи) |

### 2.3 Анимации действий

| Действие агента | Визуальная анимация | Триггер |
|----------------|---------------------|---------|
| Пишет код | Сидит за компьютером, экран мерцает, набирает текст | Git push / file edit |
| Тестирует | Лупа + чеклист, ставит галочки | Test run / issue create |
| Исследует | Читает документы, листает страницы | web_search / web_fetch |
| Пишет документ | За столом с бумагами, печатает | File write (.md, .pdf) |
| Общается | Пузыри сообщений летают между персонажами | sessions_send / message |
| Деплоит | Кнопка launch, ракета/контейнер анимация | Docker / deploy commands |
| Ревьюит PR | Смотрит в экран, ставит ✅/❌ | gh pr review |
| Ждёт задачу (idle) | Пьёт кофе / сидит, качает ногой | Нет активности > 5 мин |
| Спит | 💤 z-z-z | Нет активности > 30 мин |
| Ошибка | Красный ! над головой, взрыв | Error в логах |
| Получил задачу | Восклицательный знак, встаёт | Входящее сообщение с задачей |

### 2.4 Коммуникация между агентами

| Элемент | Визуализация |
|---------|-------------|
| Сообщение A→B | Анимированный конверт/пузырь летит от A к B |
| Задача от PM | Карточка задачи «вылетает» от PM к исполнителю |
| PR review | Документ перемещается от Dev к QA/PM |
| Групповое сообщение | Broadcast — лучи от отправителя ко всем |

## 3. Источники данных

### 3.1 OpenClaw API

| Данные | Источник | Частота обновления |
|--------|---------|-------------------|
| Статус агента (активен/idle) | `sessions_list` | Каждые 5 сек |
| Текущее действие | Последнее сообщение / tool call из `sessions_history` | Каждые 10 сек |
| Межагентные сообщения | `sessions_send` events | Real-time (WebSocket) |
| Heartbeat | Heartbeat poll/response | Каждые 30 сек |

### 3.2 GitHub API

| Данные | Источник | Частота |
|--------|---------|---------|
| Коммиты | GitHub Webhooks / `gh api events` | Real-time |
| PR статус | GitHub API / Webhooks | Real-time |
| Issues | GitHub API | Каждые 30 сек |
| CI/CD статус | GitHub Actions API | Per event |

### 3.3 Telegram / Chat

| Данные | Источник | Частота |
|--------|---------|---------|
| Сообщения в группе | Telegram Bot API / OpenClaw channel | Real-time |
| Реакции | Telegram API | Real-time |

### 3.4 Системные метрики

| Данные | Источник | Частота |
|--------|---------|---------|
| CPU / Memory | `/proc` / Docker stats | Каждые 15 сек |
| Health checks | `/health` endpoints | Каждые 30 сек |
| Error rate | Application logs | Real-time |

## 5. Технические требования

### 5.1 Архитектура

```
┌─────────────┐     WebSocket      ┌──────────────┐
│   Frontend  │ ◄─────────────────▶│   Backend    │
│  (Browser)  │                    │  (FastAPI)   │
│             │     REST API       │              │
│  Canvas /   │ ◄─────────────────▶│  Aggregator  │
│  PixiJS     │                    │              │
└─────────────┘                    └──────┬───────┘
                                          │
                          ┌───────────────┼───────────────┐
                          │               │               │
                   ┌──────▼──────┐ ┌──────▼──────┐ ┌──────▼──────┐
                   │  OpenClaw   │ │   GitHub    │ │  Telegram   │
                   │    API      │ │  Webhooks   │ │   Bot API   │
                   └─────────────┘ └─────────────┘ └─────────────┘
```

### 5.2 Frontend Stack

| Компонент | Технология | Почему |
|-----------|-----------|--------|
| Рендеринг | **PixiJS** (2D WebGL) | 60fps анимация, спрайты, эффекты частиц |
| Альтернатива | **Phaser 3** | Если нужна игровая логика (pathfinding, collision) |
| Fallback | **CSS animations** + SVG | Для простых устройств |
| UI overlay | **React** | Панели, модалки, настройки поверх canvas |
| State | **Zustand** | Легковесный, идеален для real-time state |
| Real-time | **WebSocket** (native) | Минимальная задержка |
| Charts | **Recharts** / **D3** | Timeline, статистика |

### 5.3 Backend Stack

| Компонент | Технология | Почему |
|-----------|-----------|--------|
| API + WebSocket | **FastAPI** + `websockets` | Уже используется, async native |
| Data aggregation | **Celery Beat** | Периодический сбор данных из источников |
| Cache | **Redis** | Текущее состояние агентов (TTL 60s) |
| Queue | **Redis Pub/Sub** | Real-time events → WebSocket broadcast |
| Storage | **PostgreSQL** | История событий, timeline |

### 5.4 Спрайты и ассеты

| Ассет | Формат | Описание |
|-------|--------|----------|
| Персонажи | Spritesheet PNG (16-32px base) | 6 персонажей × 10 анимаций × 4-8 кадров |
| Офис | Tilemap | Изометрический или top-down фон |
| Иконки действий | SVG / PNG | 💻 ✍️ 🔍 🧪 💬 🚀 |
| Эффекты | Particle sprites | Конфетти (задача закрыта), искры (ошибка) |
| Пузыри | SVG + CSS | Речевые пузыри с текстом |

**Стили на выбор:**

| Стиль | Описание | Сложность |
|-------|----------|-----------|
| **Pixel Art** | Ретро 16-bit, как в Stardew Valley | Средняя |
| **Low Poly** | Минималистичный 3D-стиль | Высокая |
| **Flat 2D** | Как в корпоративных иллюстрациях | Низкая |
| **Isometric** | Как в классических Sims | Средняя |

**Рекомендация:** Isometric pixel art — баланс узнаваемости (Sims-вайб) и простоты реализации.

### 5.5 Performance

| Метрика | Требование |
|---------|-----------|
| FPS | ≥ 30fps (target 60fps) |
| Initial load | < 3 секунды |
| WebSocket latency | < 500ms от события до анимации |
| Memory | < 200MB в браузере |
| Bundle size | < 2MB (без спрайтов), спрайты lazy-load |
| Спрайты | < 5MB total (compressed) |

## 6. Пользовательские сценарии

### 6.1 Руководитель (Грачья) открывает дашборд утром

```
1. Открывает dashboard.openclaw.ai
2. Видит виртуальный офис — 6 персонажей
3. Артём (PM) — 🟢 активен, пузырь: «Распределяю задачи»
4. Коля (Dev) — 🟢 активен, за компьютером: «Фикшу #71»
5. Лена (Analyst) — 🟢 активна, с документами: «UX ретест»
6. Саша (QA) — 🟡 idle, пьёт кофе
7. Дима (DevOps) — 💤 спит (ночная сессия завершена)
8. Макс (Dev) — 🟢 активен, кодит
9. В Activity Feed: последние 20 событий за ночь
10. Кликает на Артёма → видит его задачи, кому что назначил
11. Смотрит Stats: 47 коммитов, 12 issues закрыто, 3 PR merged
12. Доволен — всё под контролем без единого вопроса в чат ✅
```

### 6.2 Генри (DevOps) мониторит деплой

```
1. Открывает дашборд
2. Видит Дима (DevOps) — анимация ракеты: «Deploy PR #78»
3. Над Димой появляется прогресс-бар деплоя
4. Конфетти-эффект → деплой успешен
5. Артём автоматически получает карточку → пузырь: «Smoke test»
6. Саша получает задачу → встаёт, берёт лупу: «Тестирую»
```

### 6.3 Ошибка в системе

```
1. Коля пушит код → CI падает
2. Над Колей — красный ! и взрыв-эффект
3. Пузырь: «❌ CI failed: test_auth»
4. Артём автоматически получает уведомление
5. Анимация: карточка «fix CI» летит от Артёма к Коле
6. Коля садится за комп → «Фикшу CI»
```

## Резюме

Анимированный дашборд агентов — это не просто «красивая картинка». Это **инструмент управления**, который позволяет руководителю за 3 секунды понять состояние команды без единого вопроса. Стиль Sims делает мониторинг приятным и интуитивным.

**Ключевые решения для обсуждения:**
1. Стиль графики: isometric pixel art vs flat 2D
2. Backend: отдельный сервис vs модуль в OpenClaw
3. Источники данных: какие API OpenClaw доступны для чтения сессий
4. Приоритет: MVP за 2-3 недели vs полная версия за 6-8 недель
